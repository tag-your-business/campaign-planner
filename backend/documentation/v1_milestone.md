## Configuration Guide

### Required Environment Variables

```bash
# OpenAI API (Required)
OPENAI_API_KEY=sk-...
```

### Optional Environment Variables

```bash
# OpenAI Models
OPENAI_TEXT_MODEL=gpt-4o-mini
OPENAI_IMAGE_MODEL=dall-e-3

# Timing
GENERATION_LEAD_DAYS=10
PUBLISH_LEAD_DAYS=3

# Scheduling
GENERATE_CRON=0 8 * * *
PUBLISH_CRON=0 10 * * *

# Social Media
FACEBOOK_API_VERSION=v21.0
INSTAGRAM_API_VERSION=v21.0
FACEBOOK_ACCESS_TOKEN=...
INSTAGRAM_ACCESS_TOKEN=...

# Retry Settings
MAX_RETRIES=3
RETRY_DELAY_SECONDS=2
```

## Usage Guide

### Setup

```bash
# 1. Install dependencies
cd backend
poetry install

# 2. Configure environment
cp .env.example .env
nano .env  # Add your API keys

# 3. Prepare data
# - Add companies to data/registry/company_registry.json
# - Add company profiles to data/companies/{slug}/profile.json
# - Optionally add logos to data/companies/{slug}/logo.png
# - Add events to data/events/2026.json
```

### Running the Application

```bash
# Development mode (with auto-reload)
poetry run uvicorn app.main:app --reload

# Production mode
poetry run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

### API Documentation

Access interactive API docs at:
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

### Manual Triggers

```bash
# Trigger generation immediately
curl -X POST http://localhost:8000/api/v1/campaigns/generate

# List pending campaigns
curl http://localhost:8000/api/v1/campaigns/pending

# Trigger publishing immediately
curl -X POST http://localhost:8000/api/v1/campaigns/publish

# Get specific campaign
curl http://localhost:8000/api/v1/campaigns/{campaign_id}

# Publish specific campaign
curl -X POST http://localhost:8000/api/v1/campaigns/{campaign_id}/publish

# List companies
curl http://localhost:8000/api/v1/companies/

# Get company profile
curl http://localhost:8000/api/v1/companies/abc_dental

# Get events for year
curl http://localhost:8000/api/v1/events/2026
```

## Deployment Instructions

### Local Deployment

See "Running the Application" section above.

### Production Deployment (EC2 Ubuntu)

```bash
# 1. Install Python 3.13+
sudo apt update
sudo apt install python3.13 python3-pip

# 2. Install Poetry
curl -sSL https://install.python-poetry.org | python3 -

# 3. Clone repository
git clone <repo-url>
cd campaign-planner/backend

# 4. Install dependencies
poetry install --no-dev

# 5. Configure environment
cp .env.example .env
nano .env  # Add API keys

# 6. Create systemd service
sudo nano /etc/systemd/system/campaign-planner.service
```

**Systemd Service File**:
```ini
[Unit]
Description=Campaign Planner V1
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/campaign-planner/backend
Environment="PATH=/home/ubuntu/.local/bin:/usr/local/bin:/usr/bin:/bin"
ExecStart=/home/ubuntu/.local/bin/poetry run uvicorn app.main:app --host 0.0.0.0 --port 8000
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
# 7. Start and enable service
sudo systemctl daemon-reload
sudo systemctl start campaign-planner
sudo systemctl enable campaign-planner

# 8. Check status
sudo systemctl status campaign-planner

# 9. Monitor logs
sudo journalctl -u campaign-planner -f
```

### Health Monitoring

```bash
tail -f data/logs/app.log

du -sh data/campaigns/
```

## Known Limitations

### Technical Limitations

1. **Storage**: JSON filesystem storage
   - Not suitable for >100 companies
   - No concurrent write protection
   - Manual cleanup required

2. **Instagram Publishing**: Requires publicly accessible image URLs
   - Current implementation notes this in code
   - Workaround: Upload to Facebook first, use that URL
   - Or: Implement simple file server

3. **Error Recovery**: No automatic retry for failed campaigns
   - Failed campaigns must be manually republished
   - Planned for V1.1

4. **No Approval Workflow**: Campaigns auto-publish
   - No human review before posting
   - Planned for V2

5. **No Analytics**: No performance tracking
   - No metrics on engagement, reach, etc.
   - Planned for V2

### Operational Limitations

1. **Single Platform**: Only Facebook & Instagram
2. **Single Content Type**: Only single image posts
3. **No Video Support**: Images only
4. **No Carousel Support**: Single images only
5. **No Stories Support**: Feed posts only

## Support Information

### Logging

Logs are written to:
- Console (stdout)
- File: `data/logs/app.log` (rotated daily)

Log levels:
- INFO: Normal operations
- WARNING: Non-critical issues (e.g., missing logo)
- ERROR: Failures that need attention
- DEBUG: Detailed debugging info (when DEBUG=true)

### Troubleshooting

**Issue**: Generation fails with OpenAI API error
- Check `OPENAI_API_KEY` is valid
- Check API quota and rate limits
- Review logs for specific error message

**Issue**: Publishing fails
- Verify Facebook/Instagram access tokens
- Check token permissions (pages_manage_posts, instagram_content_publish)
- Verify page IDs and account IDs in company profiles

**Issue**: Scheduler not running
- Check application is running
- Verify cron expressions in `.env`
- Check logs for scheduler startup messages

**Issue**: Images missing logos
- Verify logo exists at `data/companies/{slug}/logo.png`
- Check logo file format (PNG with transparency)
- Review logs for branding warnings

### Data Cleanup

```bash
# Remove all generated campaigns
rm -rf data/campaigns/generated/*

# Remove logs
rm -rf data/logs/*

# Full reset (keeps companies and events)
rm -rf data/campaigns/* data/logs/*
```
